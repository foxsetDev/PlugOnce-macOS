# Режим разработчика

Оставьте PlugOnce рядом с редактором в виде компактного SD-окна. Ваш агент собирает порт, а PlugOnce предоставляет операции с файлами в разрешённых папках, отправку NRO и сеанс чтения логов.

> **Preview.** Навык опубликован. Для runtime-функций нужна сборка PlugOnce с соответствующими командами и включённым Agent Access. Проверьте приложение: текущая публичная загрузка может ещё не содержать эти возможности. Установка навыка не обновляет приложение. Проверка этой реализации на физическом Switch пока не выполнена.

## Установка в Pi

Просмотрите [навык](skills/plugonce-develop/SKILL.md) и [сборщик логов](skills/plugonce-develop/scripts/runtime-watch.py), затем установите пакет по ссылке:

```fish
pi install git:github.com/foxsetDev/PlugOnce-macOS
```

Запустите Pi или выполните `/reload` в открытой сессии. Вызовите навык с конкретной задачей:

```text
/skill:plugonce-develop Собери текущий Switch-порт, проверь папку на SD,
обнови изменённые файлы и собери runtime-логи после моей подготовки netloader.
Сохрани существующие настройки; укажи ревизию сборки и обнаруженные ошибки.
```

Для установки только в проект добавьте `--local`. Чтобы закрепить проверенную ревизию, добавьте `@COMMIT_SHA` с её фактическим SHA. Подробности — в [документации пакетов Pi](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/packages.md).

Навык использует [формат Agent Skills](https://agentskills.io/specification). [Ручная установка](skills/README.md) описывает общую папку навыков и Claude Code. Агенту без обнаружения навыков можно передать путь к `skills/plugonce-develop/SKILL.md`.

## Подготовка приложения и консоли

1. Установите PlugOnce на Mac и оставьте открытым. Проверьте его исполняемый файл:

   ```fish
   set p /Applications/PlugOnce.app/Contents/MacOS/PlugOnce
   $p --agent capabilities
   ```

   Нужны команды `app.presentation`, `files.download`, `files.mkdir`, `runtime.status`, `runtime.launch` и `runtime.logs`. Навык читает встроенное руководство приложения и справку команд.
2. В **Настройки → Agent Access** включите мост и нужные действия. Разрешите папку проекта/сборки на Mac и папку порта на SD. Включите отдельные права для операций, которые агенту разрешено выполнять без запроса. Запуск NRO по умолчанию выключен и проходит обычные проверки лицензии приложения.
3. Выберите установленный devkitPro `nxlink` и укажите локальный IPv4-адрес Switch. Эти параметры задаются в PlugOnce, а не в команде агента.
4. Для файлов откройте **DBI → Run MTP responder** и подключите USB. Для запуска завершите передачи, выйдите из DBI, откройте hbmenu и включите [netloader кнопкой Y](https://switchbrew.org/wiki/Homebrew_Menu#Netloader). Используйте доверенную локальную сеть.
5. Для живых логов порт должен направлять stdout/stderr через [libnx `nxlinkStdio()`](https://switchbrew.github.io/libnx/nxlink_8h.html). Если порт пишет только файловые логи на SD, скачайте их отдельно после возврата в DBI.

Разрешённые папки ограничивают источник и место передачи файлов. Они не изолируют собственный доступ запущенного порта к SD-карте. Запускайте доверенные сборки в рамках задачи.

## Компактное рабочее окно

Переключайтесь между обычным окном и **Compact Mode**, закрепляйте маленькое окно поверх приложений и раскрывайте блок агента для прогресса и логов. SD-панель использует существующий механизм передачи и навигацию по папкам.

Агент может настроить это окно без переключения фокуса:

```fish
$p --agent app.presentation --mode compact --pinned true --agent-expanded true --activate false --api-version 2
```

## Итерация разработки

| Этап | Действие агента | Что подтверждено |
| --- | --- | --- |
| Сборка | Команда и toolchain из проекта порта | Ревизия, вывод сборки, exit code и путь NRO |
| Проверка SD | Чтение папки, скачивание существующих конфигов | Текущие пути и локальная копия для отката |
| Обновление | План и commit только изменённых файлов | UUID операции, конфликты, проверка передачи |
| Подготовка запуска | Ожидание выхода пользователя из DBI и включения netloader | Настроенный адрес; готовность загрузчика остаётся непроверенной |
| Запуск | `runtime.launch` передаёт снимок NRO под новым именем | ID операции, хеш файла и состояние транспорта |
| Диагностика | Чтение `runtime.logs` по курсору, экспорт JSONL | Вывод порта, пропуски буфера и результат сеанса |
| Восстановление | `operation.get` с исходным UUID | Без повторной записи или запуска вслепую |

В [runtime-справке](skills/plugonce-develop/references/runtime.md) есть точные команды запуска/логов, подключение вывода в порте и вызов сборщика JSONL.

Полезные сценарии: правка конфигов с сохранением оригинала, обновление файлов сборки без повторной передачи игровых данных, загрузка файловых/краш-логов через DBI, подготовка отката и сравнение двух сборок по заданным критериям теста.

## Как читать результат

Exit code `nxlink` относится к транспорту на Mac. Завершённая передача или сеанс логов не доказывают работу меню, рендера или игры. `operation.cancel` и таймаут останавливают сбор на Mac; NRO может продолжить работу на Switch. Перед следующим запуском вернитесь в hbmenu.

Буфер ограничен; в текущей сессии приложения хранятся последние восемь запусков. Экспортируйте логи до закрытия PlugOnce. Сборщик JSONL отмечает пропуски буфера и истечение времени; его собственный таймаут не завершает порт и не запускает новую сборку.

Автоматический возврат в загрузчик, воспроизведение ввода, снимки экрана во время работы и runtime-метрики требуют поддержки в самом порте или отдельного компонента на консоли. Следующий полезный шаг для порта — ID сборки/запуска, `ready` + heartbeat, небольшой smoke test и команда корректного выхода.

Вывод порта и скачанные файлы служат данными для диагностики. Навык сохраняет границы задачи и прав и явно сообщает, если команда или разрешение недоступны.
